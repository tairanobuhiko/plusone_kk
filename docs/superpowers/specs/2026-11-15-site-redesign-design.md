# Plus One ホームページ作り直し 設計書

- 作成日: 2026-11-15
- 作業ブランチ: `worktree-redesign-rich-top`（main から分岐）

## 目的

Plus One株式会社（前橋市の建築・内装工事業）のホームページを、見た目から大きく作り直す。
今のサイトは 1 画面に 4 つのイラストを並べただけで、安っぽく見える。
訪れた人の目を惹き、問い合わせにつながるサイトにする。

## 決まったこと（依頼者が決めた内容）

- 見た目を大きく変える。動きを付けてよい。
- 見た目の方向は、見本 3 案のうち「C プラス記号」にする。
  - 明るい地色に、ロゴの紺色と黄色を使う。
  - 社名にちなんだ大きな「+1」の記号を冒頭に置く。
  - 事業名が横に流れる帯を置く。
- 会社名として目立つ場所には、文字ではなく会社ロゴの画像を使う。
- 実際の施工写真は今は無い。後から差し替える。
- git worktree で別ブランチを作って作業する。main には触れない。

## やること

1. トップページを、縦にスクロールして読む長いページに作り直す。
2. 会社概要ページ、問い合わせページを同じ見た目に合わせる。
3. ヘッダー（上部メニュー）とフッターを作り直す。
4. 動きを付ける。
5. 施工事例の枠を作り、写真を後から置き換えられるようにする。
6. テストを書く。

## やらないこと

- 問い合わせメールを送る仕組み（`pages/api/sendEmail.ts`）は変えない。
- Google アナリティクスの仕組みは変えない。
- 依存パッケージの脆弱性対応（postcss、minimatch）は別作業にする。
- ページの URL は変えない（`/`、`/about`、`/contact` のまま）。
- 新しい構成（App Router）への移行はしない。

## してはいけないこと

- 事実でない内容を載せない。架空の施工事例、架空の実績数、架空のお客様の声は書かない。
- 小さいロゴ画像を無理に引き伸ばして、ぼやけた状態で見せない。
- 動きを止める設定（OS の「視差効果を減らす」）にしている人に、動きを強制しない。
- スマートフォンで横スクロールが出る状態にしない。

## 作り方の案と採用理由

| 案 | 内容 | 判断 |
|---|---|---|
| A | 今の Next.js の構成（pages 方式）は残す。MUI をやめ、自前の CSS（CSS Modules）で作る。動きは CSS とブラウザ標準の機能で付ける | 採用 |
| B | 案 A に動き専用の部品（framer-motion など）を足す | 不採用。今回の動きは CSS で足りる。読み込むファイルが増える |
| C | App Router と Tailwind に全部移す | 不採用。見た目の出来は A と同じなのに、フォームとアナリティクスまで作り直しになる |

MUI をやめる理由は、MUI の既製の見た目が今の印象を作っているから。
MUI と emotion は `package.json` から外す。

## 見た目の決まり

### 色

| 役割 | 色 | 備考 |
|---|---|---|
| 地色 | 明るい灰白 `#f4f5f7` 付近 | |
| 主役の色 | ロゴの紺色 | ロゴ画像から色を拾って合わせる |
| 差し色 | 黄色 `#ffc928` 付近 | 既存の事業イラストの黄色と合わせる |
| 文字 | 濃い紺 `#12154a` 付近 | |

色は `styles/globals.css` に変数としてまとめ、各部品はその変数だけを使う。

### 文字

- 日本語: Zen Kaku Gothic New（太さ 400 / 700 / 900）。`next/font/google` で読み込む。
- 大きな「+1」の記号: Archivo Black。
- 見出しは太さ 900 で大きく組む。

### ロゴの使い方

| 場所 | 使う画像 | 表示の大きさ |
|---|---|---|
| ヘッダー左上 | `Plus-One_logo.png`（マークと Plus One の文字、261×123） | 高さ 44px ほど |
| スマートフォン用メニューの上部 | 同上 | 高さ 56px ほど |
| フッター | `Plus-One-CoLtd_text.gif`（Plus One Co., Ltd. の文字、705×105、背景が透明） | 幅 280px ほど |
| 会社概要ページの冒頭 | `Plus-One_logo.png` | 元の大きさ以下 |

- ロゴ画像は元の大きさより大きく表示しない。
- ロゴは白か明るい地色の上に置く（マークの内側が白抜きのため）。
- 画像の場所は `/plusone_logos/...` のように先頭に `/` を付けて書く（今は付いておらず、下の階層のページでロゴが出なくなる）。
- 冒頭の大きな「+1」は社名の表記ではなく飾りの記号なので、文字のまま残す。

## ページの構成

### トップページ（`/`）

上から順に次の並びにする。

```
[ヘッダー]  ロゴ            事業内容  施工事例  会社概要  [お問い合わせ]
---------------------------------------------------------------
[冒頭]      暮らしに、                               ＋１
            プラスワン。                         （大きな記号）
            内装も、水廻りも、外構も。...
            [お問い合わせ]  [事業内容を見る]
[流れる帯]  住宅内装リフォーム ＋ 店舗改装 ＋ 外構工事 ＋ 水廻り工事 ＋ 住宅診断 ＋ ...
---------------------------------------------------------------
[事業内容]  4 枚のカード（既存のイラスト + 事業名 + 短い説明）
[住宅診断]  紺色の帯。「大切な住まいの点検・管理 "住宅診断" 承ります」
[数字]      2016 年設立 ／ 4 つの工事 ／ 2 つの資格
[施工事例]  写真の枠 3 つ（今は「写真準備中」と表示）
[代表挨拶]  挨拶文の冒頭 + 「会社概要を見る」
[問い合わせ] 電話番号 + 「フォームで問い合わせる」
[フッター]  ロゴ、住所、電話、メニュー、コピーライト
```

- 「数字」に載せるのは会社概要にある事実だけにする（2016年7月設立、事業 4 種、二級建築士と2級建築施工管理技士）。
- 「事業内容」の短い説明文は作り手が書く仮の文章とする。公開前に代表の確認をもらう。
- 冒頭の文章も仮の文章とする。

### 会社概要ページ（`/about`）

- 代表挨拶と会社概要の表は、今の文章をそのまま使う。
- 見出しと表の見た目を新しい色と文字に合わせる。
- 表に `<tbody>` を足す（今は抜けていて、開発中に警告が出る）。

### 問い合わせページ（`/contact`）

- 入力項目（名前、メール、本文）と送信の流れは今のまま。
- 見た目を新しい色と文字に合わせる。入力欄の上に項目名を表示する。
- 送信中と送信結果の表示は、MUI の部品をやめて自前の部品に置き換える。
- 入力不足のときは、ブラウザの `alert` ではなく入力欄の近くに文章で知らせる。

### ヘッダーとフッター

- ヘッダーは画面上部に固定する。パソコンではメニューを横並びにする。
- スマートフォン（幅 640px 未満）では、ボタンを押すとメニューが開く形にする。
- トップページの「事業内容」「施工事例」は、同じページ内の該当位置へ移動するリンクにする。

## 動き

| 場所 | 動き |
|---|---|
| 冒頭の「+」 | ときどき 90 度回る |
| 流れる帯 | 事業名が右から左へ流れ続ける |
| 各ブロック | 画面に入ったときに下からふわっと現れる |
| 数字 | 画面に入ったときに 0 から数え上がる |
| カード、ボタン | マウスを乗せたときに少し浮く |

- OS の「視差効果を減らす」が有効なときは、動きを止めて最初から完成した状態で見せる。
- JavaScript が動かない場合でも、内容はすべて読める状態にする。

## 施工事例の差し替え方

- 事例の一覧は 1 つのファイル（`data/works.ts`）にまとめる。1 件は「題名」「説明」「写真ファイル名」を持つ。
- 写真は `public/works/` に置く。
- 写真ファイル名が空の事例は「写真準備中」の枠を表示する。
- 写真が届いたら、`public/works/` に写真を置き、`data/works.ts` にファイル名と題名を書くだけで反映される。
- 差し替えの手順は `README.md` に画面操作の順で書く。

## あわせて直す点

- ページの言語設定を日本語にする（`lang="en"` を `lang="ja"` に）。
- ページの説明文を、初期値の「Generated by create next app」から会社の説明に変える。
- 各ページのタイトルを分ける（例: 「会社概要 | Plus One株式会社」）。
- 3 ページで重複している `<Head>` とヘッダー、フッターの記述を、共通の部品 1 つにまとめる。

## テスト

- テスト用の道具として vitest、@testing-library/react、jsdom を開発用に追加する。
- 次の内容をテストする。
  - 施工事例: 写真がある事例は写真を、無い事例は「写真準備中」を表示する。
  - ヘッダー: メニューの項目とリンク先が正しい。スマートフォン用メニューが開閉する。
  - 数字の数え上げ: 最後に正しい値になる。動きを止める設定では最初から最終値を表示する。
  - 問い合わせフォーム: 入力不足のときに送信せず、知らせを表示する。送信成功と失敗で表示が変わる。
  - ロゴ: 画像の場所が `/` で始まる。
- あわせて `npm run lint` と `npm run build` が通ることを確認する。
- テストケースと結果は `~/.claude/test_result/` に保管する。

## 作り手に任せる点

- 部品の分け方とファイル名。
- 余白や文字の大きさの細かい数値。
- 既存のイメージ写真（`hero_image*.jpg`）を使うかどうか。
- 使わなくなったファイル（MUI を使う部品、古い CSS）の削除。

## 作り手が決めた点（依頼者が決めたものではない）

- MUI と emotion を外す。
- vitest などテスト用の道具を追加する。
- 3 ページの構成と URL を残す。
- トップページのブロックの並び。
- 施工事例が無い間は「写真準備中」の枠を見せる（枠ごと隠すのではなく）。
- 冒頭の「+1」は文字のまま残す。

## 気がかりな点

- ロゴ画像が小さい（最大で 261×123）。高精細な画面では少しぼやける可能性がある。元データ（大きい画像やベクター形式）があれば差し替えたい。
- 「写真準備中」の枠が出たまま本番に出すと、未完成に見える。本番に出す時点で写真が無ければ、施工事例のブロックを一時的に隠す選択肢がある。
- 事業の説明文と冒頭の文章は仮のもの。代表の確認が要る。
